## 왜 이렇게 했나

- **브라우저는 Outlook · .pst 를 못 읽는다**는 것을 먼저 기획서 · README 에 적었습니다. 「02 페이지 버튼 하나로」는 웹만으로 불가능하고, Graph API 는 승인이 필요한 데다 .pst 를 못 읽습니다. 클래식 Outlook 의 COM 은 Online 과 .pst 를 같은 방법으로 보여 주고 Windows 기본 PowerShell 로 쓸 수 있어, 「설치 없이 한 번 클릭」에 가장 가깝습니다.
- **수집기와 도구 사이를 manifest.json 하나로 약속**했습니다. 수집기는 Outlook 이 있는 PC 에서만 돌고, 도구는 어디서나 돕니다. Graph 가 승인되면 수집기만 바꾸면 됩니다.
- **자동 열기는 스크립트 파일(manifest.js)로** 넘깁니다. file:// 페이지는 다른 file:// 파일을 fetch 로 읽을 수 없지만 `<script>` 로는 불러올 수 있습니다. 대신 이 통로를 file:// 로 연 도구가 file:// 의 `manifest.js` 만 부르도록 막았습니다(온라인 주소에 `#/make?collect=https://…` 를 붙여 남의 스크립트를 부르는 공격 통로가 되지 않게).
- **PDF 는 브라우저에서** 읽습니다. 무설치로 쓸 수 있는 PowerShell PDF 해석기가 없고, 한글 PDF 는 글꼴 표(CID)까지 풀어야 해서 직접 짜면 틀리기 쉽습니다. pdf.js 는 이미 data09-26 에서 file:// 로 검증했습니다.
- **Office 글 뽑기를 두 벌(PowerShell · JS) 같은 규칙으로** 짰습니다. 수집기는 Windows 에서만 돌아 macOS 에서는 JS 로 시험하고, Windows 에서는 `Test-Collector.ps1` 이 두 결과를 글자 단위로 대조합니다. 이번에 휴대용 pwsh 로 실제 대조까지 했습니다(.NET 정규식의 `$` 가 끝 줄바꿈 앞에서도 맞는 차이를 `\z` 로 맞춤).
- **Restrict 날짜 형식은 PC 지역 설정을 탑니다**(Outlook 문서의 알려진 함정). 틀리면 조용히 0 건이 되므로, 0 건인데 폴더의 최신 메일이 기간 안이면 훑기로 대신하고 알림을 남기게 했습니다.
- **첨부 문장은 본문과 겹치면 뺍니다.** 회의록 첨부에 본문과 같은 결정이 또 적혀 있는 경우가 많아, 그대로 넣으면 같은 실적이 두 번 나옵니다(유사도 0.6).
