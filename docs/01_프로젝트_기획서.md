## 1. 추진 배경과 현안

- data09-10 과제 B 1단계는 메일을 **사람이 .eml 로 내보내 도구에 넣는** 방식이었습니다(폴더 고르기 · 기간 입력 · 파일 고르기).
- 실제로 보고서에 쓰는 메일은 Online 사서함(회사 메일 계정 여러 개)과 **내 PC 로 옮겨 둔 백업(.pst)** 에 나뉘어 있고, 폴더가 연도 · 프로젝트별로 수십 개라 손으로 고르기 어렵습니다.
- 디자인 업무의 근거는 본문보다 **첨부**(회의록 워드, 시안 PPT, 평가표 엑셀, 도면 PDF, 렌더링 그림, 일러스트 .ai)에 많습니다. 1단계는 첨부의 이름만 봤습니다.
- 요청: 사용자는 **주간 · 월간만 고르고**, 그 기간에 주고받은 Online · Local 메일과 첨부를 **자동으로 찾아 분석**해 업무보고 형식으로 써 주기.

## 4. 해결 방안 개요

### 4.1 먼저 — 솔직한 현실 점검

- **웹페이지(브라우저)는 Outlook 이나 .pst 를 직접 읽을 수 없습니다.** 브라우저는 보안상 사용자가 고른 파일만 읽고, 내 PC 의 프로그램에 들어갈 수 없습니다. 「02 페이지에서 버튼 하나로 Outlook 을 읽는」 형태는 웹만으로는 불가능합니다.
- **Graph API** 는 서버에서 Online 사서함을 읽을 수 있지만 IT 승인이 필요하고, **.pst(Local 메일)는 Graph 로도 읽지 못합니다**(내 PC 의 파일이라서).
- **.pst 파일을 직접 해석**하는 방법도 있지만 형식이 복잡하고(바이너리 · 압축 · 암호화 옵션) 신뢰할 만한 무설치 도구가 없습니다.
- 그래서 가장 현실적인 길은 **Outlook 자신에게 물어보는 것**입니다. 클래식 Outlook 은 COM 이라는 통로로 다른 프로그램이 메일을 읽게 해 주고, Outlook 에 열린 .pst 도 Online 사서함과 똑같이 보입니다. Windows 기본 PowerShell 로 쓸 수 있어 설치가 필요 없습니다.

### 4.2 구성 — 내 PC 수집기 + 브라우저 보고서 도구

```
 주간보고.bat ─▶ 수집기(PowerShell · Outlook COM · 읽기 전용) ─▶ 수집 폴더(manifest.json · 첨부) ─▶ 업무보고 도구(브라우저) ─▶ 보고서
```

| 부분 | 하는 일 |
|---|---|
| `주간보고.bat` · `월간보고.bat` | 더블클릭용. 이번 · 지난 기간을 묻고 수집기를 실행(이 파일 하나만 실행 허용) |
| 수집기 `collector/Collect-OutlookMail.ps1` | 켜진 Outlook 에 붙어 모든 데이터 파일(Online · .pst) → Online 은 받은 · 보낸 편지함, .pst 는 모든 메일 폴더(지운 편지함 · 정크 · 제외폴더 빼기) → 기간 안 메일 → 첨부 저장 · 글 뽑기 → `manifest.json` → 도구 자동 열기 |
| 수집기 부품 `collector/CollectorCore.ps1` | Outlook 과 상관없는 부분: 워드 · PPT · 엑셀 글 뽑기(zip 안 XML), 기간 계산, 설정 읽기, JSON 쓰기 |
| 설정 `collector/수집설정.txt` | Online폴더 · PST폴더 · 제외폴더 · 저장위치 · 첨부 크기 한도 등(메모장으로 고침) |
| 업무보고 도구 `index.html` | 02 한 화면(주간 · 월간 → 모은 메일 → 보고서 만들기), PDF · 일러스트 글 뽑기(pdf.js), 분류 · 양식 표 · Word/Excel(data09-10 로직) |
| 보고서 취합 `js/rollup-logic.js` · 08 화면 | 보고서 파일(.json) 내보내기 · 여러 사람 파일 취합(v0.2, 5.5) · 받은 메일 첨부에서 보고서 파일 찾기(v0.3, 5.6) · 임원 보고용 요약 — 임시 양식(v0.3, 5.7) |

### 4.3 왜 이렇게 나눴나

- **수집은 PC 에서, 판단은 브라우저에서.** 수집기는 Outlook 이 있는 PC 에서만 돌 수 있고, 보고서 로직은 data09-10 에서 이미 검증된 브라우저 코드입니다. 둘 사이를 `manifest.json` 한 파일로 약속해 각각 고치고 시험할 수 있습니다.
- **자동으로 열기** — 수집기가 수집 폴더에 `보고서_열기.html` 을 만들어 도구를 `#/make?collect=…/manifest.js` 로 엽니다. 브라우저가 file:// 폴더를 마음대로 읽지 못하므로 목록은 스크립트 파일(`manifest.js`), PDF 는 `pdfdata.js` 로 함께 넘깁니다. 이 통로는 내 PC 에서 연 도구가 내 PC 의 `manifest.js` 를 여는 경우만 허용합니다(온라인 주소에서 남의 스크립트를 불러오는 통로가 되지 않게).
- **Graph API 가 승인되면** 수집기만 바꾸면 됩니다(같은 `manifest.json` 을 만들면 도구는 그대로).

## 5. 주요 기능

### 5.1 수집기 (내 PC · 읽기 전용)

| 기능 | 내용 |
|---|---|
| 연결 | 켜져 있는 클래식 Outlook 에 붙음(GetActiveObject). Outlook 이 꺼져 있으면 새로 띄우지 않고 「Outlook 을 먼저 켜 주세요」 안내 후 끝냄(v0.2 — 늘 켜 둔다는 답변). 몰래 띄운 Outlook 은 화면에 안 보여 끄기 어렵기 때문 |

| .pst 자동 열기(선택) | `PST폴더` 의 .pst 중 Outlook 에 안 열린 것을 `AddStoreEx` 로 잠깐 열고 끝나면 `RemoveStore` 로 닫음. 읽기 전용 파일 · 잠긴 파일은 건너뛰고 알림 |
| 폴더 — Online | **받은 편지함 · 보낸 편지함 두 폴더만**(v0.2, 수집설정 `Online폴더=받은보낸` 기본). 기본 폴더 번호(olFolderInbox = 6 · olFolderSentMail = 5)로 찾아 Outlook 언어와 상관없음. 못 찾으면 맨 위 폴더 이름(받은 편지함 · Inbox · 보낸 편지함 · Sent Items)으로 한 번 더. `받은보낸하위` = 두 폴더와 하위 폴더, `전체` = 모든 메일 폴더 |
| 폴더 — .pst | 모든 메일 폴더 · 하위 폴더(일정 · 연락처 폴더 제외) — 답변은 Online 에 대한 것이고 .pst 는 연도 · 프로젝트별 폴더에 메일이 있어 설계대로 둠. 지운 편지함 · 정크 메일은 기본 폴더 ID 와 이름으로 늘 뺌, 나머지는 `제외폴더` |
| 기간 | 받은 메일은 ReceivedTime, 보낸 편지함은 SentOn. `Items.Restrict` 로 거르고, 0 건인데 최근 메일이 기간 안이면(PC 지역 설정의 날짜 형식 차이) 최신순 훑기로 대신함. 모든 메일의 날짜를 한 번 더 확인 |
| 같은 메일 | Message-ID 가 같으면 한 번만(Online 과 .pst 에 둘 다 있는 경우) |
| 메일 칸 | 보낸이(Exchange 주소는 SMTP 로) · 받는이 · 참조 · 날짜 · 제목 · 본문 · Message-ID · 회신 흐름 · 데이터 파일 · 폴더 · 보낸/받은 |
| 첨부 | 서명 로고 같은 숨은 그림 · 작은 그림은 뺌. 크기 한도를 넘으면 이름만. 워드 · PPT · 엑셀은 zip 안 XML 을 바로 읽어 글(Office 를 띄우지 않음), PDF · PDF 호환 .ai 는 도구가 읽도록 넘김, 그림은 이름 · 크기, 옛 Office · HWP 는 이름만 |
| 업무보고 파일(.json) | (v0.3) 첨부 .json 중 앞 4096자에 형식 표시 `"schema": "p27-report-file-v1"` 가 있는 것(5MB 이하)만 「업무보고 파일」(kind · extract = report)로 표시하고 글을 `reports.js` 에 담음. 다른 .json 은 이름 · 크기만. **첨부저장=아니오여도 이 파일은 남김**(PDF 와 같은 예외). 크기 한도는 다른 첨부와 같이 첨부최대MB(30MB) |
| 결과 | `문서\업무보고_수집\시작일_주간_날짜\` 에 manifest.json · manifest.js · pdfdata.js · reports.js(v0.3) · att\메일ID\첨부 · 첨부.txt · 수집기록.txt · 보고서_열기.html |
| 읽기 전용 | 메일을 옮기기 · 지우기 · 읽음 표시 · 보내기 · 저장하지 않음. 지우는 것은 방금 내가 저장한 첨부 복사본뿐(첨부저장=아니오일 때) |

### 5.2 업무보고 도구 — 02 한 화면

1. **주간 · 월간** — 두 칸 중 하나. 보고 기간은 모은 기간에 맞춰 둠(기준일로 바꿀 수 있음). 고른 기간이 모은 기간보다 넓으면 「다시 모아 주세요」.
2. **모은 메일 열기** — .bat 로 모으면 자동으로 열림. 아니면 「수집 폴더 열기」(폴더째) · 「파일로 고르기」 · 「예시 수집 결과로 해 보기」. 요약: Online · .pst · 보낸 메일 수, 첨부 상태(글 뽑음 · 이름만 · 못 읽는 형식), 읽지 않은 폴더, 같은 메일 수.
3. **보고서 만들기** — 규칙 분류(본문 + 첨부 글) → 이전 승인 보고서의 계획과 비교 → 「06 보고서」.
- 대안: .eml 끌어 놓기 · 붙여 넣기(수집기를 못 쓰는 PC). .eml 안에 첨부 원본이 있으면 그 글도 뽑음.

### 5.4 보고서 (data09-10 과제 B 그대로)

업무 묶기(회신 흐름 · 정규화 제목) → 실적 · 계획 · 이슈(규칙, 선택: AI 반자동 · 사내 LLM 자동 보내기) → 이전 보고서 계획 대비 → 주간보고 양식 표 · 01~03 절 · 근거 메일 → 검토 · 승인 → Word · Excel · 인쇄. 확인되지 않은 완료 · 상충 · AI 추론 · 근거 없음은 「확인 필요」로 표시.

### 5.5 보고 단계 · 보고서 취합 (v0.2 — 2026-09-30 답변)

| 규칙 | 내용 |
|---|---|
| 보고서 파일(p27-report-file-v1) | 보고자 · 단계 · 보고 단위 · 기간 · 승인 여부 · 항목(실적 · 계획 · 이슈 문장, 상태, 프로젝트, 확인 표시, 근거 메일 ID) · 근거 메일의 날짜 · 보낸이 · 제목 · 첨부 이름 · 주간보고 양식 표. **메일 본문 · 첨부 글은 넣지 않음**(Word 보고서와 같은 범위) |

### 5.6 보고서 파일을 메일로 주고받기 (v0.3 — 2026-09-30 답변 「메일로 송/수신」)

보내는 쪽과 받는 쪽 모두 지금 쓰는 Outlook 메일로 합니다. 이 도구는 메일을 보내지 않습니다.

| 쪽 | 흐름 |
|---|---|
| 보내는 사람(팀원 · 파트리더 · 팀장) | 「06 보고서」(또는 「08」의 취합본)에서 보고서 파일(.json)을 내려받으면 **안내 창**이 뜸: ① Outlook 새 메일(또는 보고 요청 메일에 회신) ② 「파일 첨부」로 다운로드 폴더의 그 파일 ③ 보내기. 「제목을 채운 새 메일 열기」(mailto: — 제목 `[주간업무보고] 기간 보고자(단위) [단계 취합] [— 초안]` · 본문 두 줄). **mailto 로는 첨부를 넣을 수 없어** 파일은 직접 첨부한다고 화면에 적음 |
| 받는 사람(파트리더 · 팀장 · 임원) | 평소처럼 `주간보고.bat` 로 메일을 모으면 수집기가 받은 메일 첨부의 보고서 파일을 알아봄(5.1). 도구는 자동 열기(reports.js) · 수집 폴더 열기(파일을 읽음) 어느 쪽이든 **형식 표시와 파일 점검(parsePackage)을 통과한 것만** 골라 「08 보고서 취합」에 **「받은 메일에서 찾은 보고서 파일 N개 불러오기」** 로 보여 줌(보낸이 · 받은 때 · 보고자 · 기간 · 승인 여부 · 첨부 이름). 02 화면에도 「N개를 찾았습니다」 안내 |
| 고르기 규칙 | 같은 파일(보고자 · 단위 · 기간 · 만든 때가 같음)이 여러 메일에 있으면(전달 · 재발송) 한 번만. 최근 메일부터. **내가 보낸 메일의 파일은 처음에 고르지 않음**(내 취합본을 다시 넣지 않게). 이미 넣은 파일은 「이미 넣음」. 형식 표시는 있는데 점검에 실패한 파일은 이유와 함께 알림 |
| 그대로 둔 것 | 파일 직접 고르기 · 끌어 놓기(공유 폴더 · 메신저로 받은 경우) |

### 5.7 임원 보고용 요약 — 임시 양식 (v0.3 — 2026-09-30 답변 「담당 임원에게는 다른 양식으로 송부」)

실제 임원 보고 양식을 아직 받지 못해, **양식을 받기 전까지** 쓰는 한 장짜리 요약을 「08 보고서 취합」에 두었습니다. 문서 제목 아래에 늘 **「임시 양식 — 실제 임원 보고 양식을 받으면 맞춥니다」** 를 적습니다.

| 부분 | 내용 |
|---|---|
| 건수 표 | 파트(보고 단위)마다 보고자 수 · 실적(완료) · 다음 주(달) 계획 · 이슈(지연 · 의사결정) · 확인 필요, 맨 아래 합계 |
| 파트별 | 핵심 실적(완료 먼저) · 주요 이슈(의사결정 필요 → 지연 → 나머지) · 다음 주 계획(날짜 빠른 순, 날짜 표시) — 각 3건, 넘으면 「외 N건 — 취합 보고서 참고」 |
| 내려받기 | Word(.doc) · HTML, 화면 미리보기 |
| 파트 나누기 | 취합한 파일의 보고 단위(없으면 보고자). 팀장 취합이면 파트리더 파일 = 파트 |

로직 `execSummary` · `execSummaryHtml`(순수 함수), 테스트는 팀장 취합(A파트 김가상 · 이가상, B파트 한가상)의 손으로 센 값.

## 7. 기술 구성

| 부분 | 기술 | 이유 |
|---|---|---|
| 수집 | Windows PowerShell 5.1 + Outlook COM | Windows 기본, 설치 · 관리자 권한 · Graph 승인 없음. Online 과 .pst 를 한 방법으로 |
| Office 글 뽑기 | .NET System.IO.Compression(zip) + 정규식 | Office 없이도, 빠르고 파일을 바꾸지 않음. 브라우저 쪽 JS 와 같은 규칙(쌍둥이)으로 짜서 서로 대조 |
| PDF 글 뽑기 | pdf.js(vendor) | 무설치로 쓸 수 있는 PowerShell PDF 해석기가 없어 브라우저에서. 스캔 PDF 는 OCR(2단계) |
| 보고서 | data09-10 과제 B 로직(순수 JS) · SheetJS · JSZip | 검증된 로직 재사용. file:// 로도 동작(외부 CDN 없음) |
| AI | **사내 LLM(OpenAI 호환 주소) 권장** + 반자동(복사 · 붙여 넣기) | 사내 LLM 이 있다는 답변(v0.2). 모델은 **qwen3.8**(v0.3 답변 — 모델 칸 기본값), 주소는 확인 전. 요청은 vLLM · Ollama 등 OpenAI 호환 서버 공통 모양(`POST …/v1/chat/completions` · model · messages). Qwen3 의 생각하는 부분 `<think>…</think>` 는 떼고 답만 읽음(자동 보내기 · 붙여 넣기 모두). 서버에 올라간 정확한 이름은 「모델 목록 불러오기」(`GET …/v1/models`)로 확인 — 예: Ollama 는 `qwen3:8b` 처럼 적음. 키는 사용자가 도구에 입력하고 코드에 없음 |
| 보고서 취합 | 보고서 파일(JSON) 주고받기 + 순수 JS 취합 | 서버 · DB 없이 메일 첨부 · 공유 폴더로 충분. 여러 단계로 같은 파일 모양이 이어짐. 받은 메일 첨부는 수집기가 이미 모으므로 추가 연결 없이 자동으로 찾음(v0.3) |

### 7.1 보안

- 수집기 · 도구 모두 인터넷 · 서버에 연결하지 않습니다. 메일 · 첨부는 내 PC 의 수집 폴더와 브라우저 저장소에만 있습니다.
- AI 는 사용자가 직접 주소를 넣고 「보내기」를 누를 때만 그 주소로 보냅니다. 외부 AI 에 붙여 넣기 전에는 회사 보안정책을 확인해야 합니다(도구에 안내).
- 자동 열기 통로는 file:// 로 연 도구가 file:// 의 `manifest.js` 만 불러오도록 제한했습니다.
- DB(2단계)에는 메일 본문과 첨부 글을 두지 않는 설계입니다(보고서 항목 문장과 근거 메일 ID · 첨부 이름만).

### 10.2 남은 질문

1. **사내 LLM 주소** — 「…/v1」 로 끝나는 OpenAI 호환 주소(예: `https://llm.사내도메인/v1`, vLLM 은 보통 포트 8000 · Ollama 는 11434). 사내 IT · LLM 담당에게 확인해 주세요. 주소를 넣은 뒤 「모델 목록 불러오기」를 한 번 눌러 서버에 올라간 모델 이름이 `qwen3.8` 그대로인지(예: `qwen3:8b` 로 보이는지) 알려 주세요. 키는 도구에 직접 입력하므로 알려 주지 않으셔도 됩니다. 브라우저에서 바로 부르려면 서버가 CORS 를 허용해야 합니다.
2. **임원 보고 양식 샘플** — 담당 임원에게 보내는 양식의 **빈 양식**, 또는 **내용을 지운 샘플**(Word · Excel · PPT · 캡처 무엇이든)을 보내 주세요. 칸 이름 · 순서 · 분량(한 장 · 여러 장)을 그대로 맞추겠습니다. 실제 보고 내용 · 이름 · 숫자는 지워 주세요.
3. **첫 실행 결과(`-ListOnly`)** — 회사 PC 에서 `-ListOnly` 로 돌린 데이터 파일 · 폴더 목록, 폴더별 메일 수, 걸린 시간, 오류 문장(메일 내용은 보내지 마세요).
